# Project Status - GeminiProxy

## Current Status
Successfully completed and verified all requested logging, compactor, GUI refinements, and the new BSOD-free System VPN Routing feature:
1. **System VPN Routing & Switcher (BSOD-Free)**:
   - Added a new **System VPN Routing** section to the left VPN control panel in the GUI.
   - Built a toggle switch "Route All PC Traffic" and a dropdown menu to select the target tunnel (VPN 1 to VPN 6).
   - **BSOD-Free route.exe Implementation**: Replaced all PowerShell-based routing commands (`Set-NetIPInterface`, `Set-NetRoute`, `Remove-NetRoute` loop) with the standard Windows `route.exe` utility via `subprocess.run` using the **Split Default Routes** (`0.0.0.0/1` and `128.0.0.0/1`) technique. This completely bypasses the Windows `Ndu.sys` kernel bug and prevents any BSODs.
   - **Interface Index Resolution**: Dynamically resolves the numeric `InterfaceIndex` of the target tunnel interface using `Get-NetIPInterface` to pass it to the `route ADD ... IF <index>` command.
   - **Stabilization Delay**: Added a 2.0-second non-blocking delay in the GUI's background thread after starting a tunnel service to let the Wintun adapter fully stabilize in the kernel before applying the routes.
   - **Heartbeat & GUI Polling Sync**: Exposed `"system_vpn_active"` and `"system_vpn_index"` state variables in `config_rotation.json` so that both the FastAPI server's background heartbeat loop and the GUI's status polling loop automatically skip checking other tunnels while the system VPN is active, keeping them green and preventing false-offline restarts.
   - **Removed PowerShell Route Mutations**: Replaced the remaining `New-NetRoute` PowerShell cmdlet inside `vpn_manager.py:207` (for VPS bypass) with a safe `route.exe ADD ...` command.
   - **Replaced Heartbeat Route cmdlets**: Replaced `New-NetRoute` in `rotation.py:177` and `server.py:239` with safe `route.exe ADD ...` commands using dynamically resolved interface indexes.
   - **System VPN Active Guard**: Configured both `rotation.py` and `server.py` to skip adding default routes to other tunnels when `system_vpn_active` is true, preventing route churn and concurrency conflicts.
   - **Stale Route Cleanup**: Added automatic cleanup of the VPS bypass route using `route DELETE` in `disable_system_routing`.
   - **Resolved VPN Interface Alias Bug**: Fixed a critical bug in `get_home_gateway_and_interface` where active VPN tunnels (named `vpn1` to `vpn6`) were mistakenly selected as the physical home interface (because they didn't match `*WireGuard*`), causing routing loops and BSODs. Excluded `vpn*` aliases to ensure the real physical interface is always resolved.
   - **Fixed Typo**: Fixed a crash-inducing typo in `vpn_manager.py` where `subprocess.DEVDEVNULL` was used instead of `subprocess.DEVNULL`.
   - **Check Tunnels IP (External IP Check)**: Added a purple "Check Tunnels IP" button to the sidebar. It launches parallel background requests (via bound `httpx.Client` transports) to fetch and report the public IPv4 address of every active tunnel on the fly, providing immediate visual routing verification.
   - **Reset to Defaults**: Added an orange "Reset to Defaults" button to the sidebar. It prompts for confirmation, turns off System VPN, clears all custom routes, and cleanly uninstalls all 6 WireGuard services, fully restoring the default Windows routing table and reverting all changes.
   - **Smart Log Autoscroll Control**: Intercepts the underlying text widget's `yscrollcommand` to dynamically track the user's scroll position. If the user scrolls up manually (visible fraction bottom `< 0.99`), autoscrolling is automatically paused to let them read historical logs. If they scroll back down to the bottom (visible fraction bottom `>= 0.99`), autoscrolling is instantly restored.
   - **Cyrillic Keyboard Shortcut Copy/Select-All Fix**: Mapped Cyrillic keyboard layouts (e.g., Russian 'с' for Copy and 'ф' for Select All) and Windows physical keycodes (`67` for C, `65` for A) directly to Tkinter's virtual `<<Copy>>` and select-all actions under the `<Control-KeyPress>` event, ensuring the log remains copyable when a Cyrillic keyboard layout is active.
   - **Removed Anomalies Tab**: Cleanly removed the unused "Anomalies" tab from the main GUI tabview, streamlining the user interface.
2. **Suppressed Headroom Errors**: Downgraded all startup dependency and monkey-patch warnings/errors in `proxy_core/compactor.py` from `ERROR` to `DEBUG` to prevent log pollution when headroom/tree-sitter is missing or disabled.
3. **Unified Context Compaction Log**: Combined multi-line compaction statistics into a single-line summary string and removed `" Context Compaction: "` text from the output.
4. **Unified Stream Logging**:
   - Aligned both `STREAM START` and `STREAM END` logs to have the exact same format (`[{provider_name}/{candidate_model}] [vpn#{actual_vpn_index}] ...`).
   - Removed the `[INFO]` level prefix from both logs by implementing a custom `PlainFormatter` (and updated `ColoredFormatter`) that supports `extra={"no_level": True}`.
   - Removed brackets `[]` around `STREAM START` and `STREAM END`.
   - Integrated token usage metrics directly into the `STREAM END` log and removed the `"[Usage]"` substring for extra compactness.
   - Suppressed redundant stream transmission logs.
   - **Stream Start for All Models**: Extended `is_streaming_request` detection in `proxy_core/server.py` to inspect the request body for `"stream": true`, enabling `STREAM START` logs for all providers (OpenRouter, Mistral, Ollama, etc.) instead of just Gemini.
   - **STREAM START Key Block Reordering**: Adjusted the key block `[key#...]` in the `STREAM START` log to go after the `STREAM START` label, keeping the logs extremely neat and logical.
5. **Single-Line Error Logging**: Added a robust JSON error parser `format_error_message` to log upstream API errors on a single line with error code, status, and message instead of raw multi-line JSON dumps.
6. **Traceback Suppression**: Removed long tracebacks from connection/network error logs.
7. **GUI Enhancements**:
   - Made the main log window another 50px wider (updated geometry to `1200x700`).
   - Added a concise row of 6 colored VPN status lamp indicators with hover tooltips to the sidebar (left panel) for real-time status tracking on the main screen.
   - Automatically activate VPN tunnels on GUI startup with a 1-second delay.
   - **Clickable VPN Lamps for Single Tunnel Restart**: Configured both sidebar and tab status indicators to have `cursor="hand2"` and bound click events to trigger background restarts of individual VPN tunnels, providing immediate yellow visual feedback during the restart.
   - **Restored Log Colors**: Reverted console/file log formats to include `[levelname]` for standard logs, and implemented keyword-based color tagging in the GUI's `poll_queue` to color the `no_level` logs (e.g. `STREAM START`, `STREAM END`, `[200]`, `[Compactor]`, `[VPN ...]` with warning subclassification for check failures/timeouts). All text is inserted via standard Tkinter `_textbox` to guarantee color tags are fully rendered.
8. **503 Error Enhancements**:
   - **VPN Rotation on 503 Errors**: Integrated 503 errors into the consecutive error tracking so that VPN tunnels are rotated immediately when the error threshold is reached, matching the 429 and network error behavior.
   - **Randomized 503 Sleep**: Replaced the static 60.0s sleep after 3+ consecutive 503 errors with a randomized sleep duration between 15.0s and 90.0s to prevent synchronized request spikes and retry collision.
9. **Session-Only Chat Logging**:
   - Removed the global legacy chat log file writing (`chat_log_YYYY-MM-DD.txt`) in `proxy_core/helpers.py`. Chat logs are now written exclusively to the session-based directories, keeping the file system clean and organized.
10. **Blacklisted tokensave Tools in Compactor**: Added 12 `tokensave` tools to `BANNED_COMPRESSED_TOOLS` blacklist in `proxy_core/compactor.py` to prevent them from being compressed or processed during context compaction.
11. **VPN Retry Logic**: Added retry logic for VPN startup and restarts:
    - `proxy_core/rotation.py`: `restart_vpn_service()` now returns `bool` (result of `wait_for_adapter_and_add_route`).
    - `proxy_core/gui.py`: `start_single_tunnel` in `on_vpn_start_tunnels` retries up to 3 times with service restart between attempts if route initialization fails.
12. **Optimized Startup Speed**: Relocated VPN startup to the beginning of `ProxyGUI.__init__`, added `hasattr` guards for early UI access, rewrote `launch_gui.cmd` to use `.venv` with `uv venv` + `uv pip install` + `-m compileall` precompilation for instant subsequent launches.
    - `proxy_core/gui.py`: `run_restart()` in `on_restart_single_tunnel` retries up to 3 times if `restart_vpn_service()` returns False.
    - All retry attempts log warnings and report success/failure status.
13. **Smart Prefix Matching & Heavy lean-ctx Blacklisting**: Implemented smart prefix matching in `prune_mcp_xml_descriptions` to automatically blacklist double-prefixed `tokensave_tokensave_` tools when the base `tokensave_` name is blacklisted. Also blacklisted heavy/redundant `lean-ctx` tools (`ctx_delta`, `ctx_multi_read`, `ctx_overview`, `ctx_knowledge`) to optimize the prompt context.
14. **Startup Optimization & Early VPN Start**: Relocated VPN tunnel startup to the very beginning of `ProxyGUI.__init__` to run in parallel with UI construction and server initialization. Added robust widget guards to prevent errors during early initialization. Rewrote `launch_gui.cmd` to use a local virtual environment (`.venv`) with `uv pip` and precompiled Python files, resulting in instant, millisecond-level startup times.
15. **HTTP 401 Error Logging**:
    - Modified `log_non_429_error` in `proxy_core/rotation.py` to accept and log HTTP 401 Unauthorized errors in `error_keys_log.json`.
    - Explicitly added `elif response.status_code == 401:` in `proxy_core/server.py` to log HTTP 401 errors and call `log_non_429_error`.
    - Added a unit test `test_401_error_logging_only_by_key` in `test_compactor.py` to verify the full lifecycle of HTTP 401 logging, count increment, and key removal.
16. **Google Provider Support in Model Manager**:
    - Added "Google" provider support to the Model Manager across both `proxy_core/gui.py` and `proxy_core/server.py`.
    - Implemented live model listing (`listmodels`) from the Google Gemini API (`https://generativelanguage.googleapis.com/v1beta/models`) using configured API keys, stripping the `models/` prefix for clean display.
    - Added support for testing individual Google models via `/control/test_model` endpoint.
    - Integrated dynamic registration and routing for google-prefixed models (e.g., `google/gemini-1.5-flash`), resolving them securely to the Gemini provider.
    - Added a unit test `test_google_model_routing` in `test_compactor.py` to verify the routing/registration logic.

All tests passed successfully and changes have been fully committed and pushed.
