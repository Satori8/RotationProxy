28. **Gemini SSE willContinue Framing & Tool-Call Finish Fix (force-model chat empty/400 fixes)**:
    - **Root cause**: Translated Gemini SSE chunks lacked `willContinue: true`. The newer @ai-sdk/google bundled in OpenCode 1.18.18 treats a chunk without `willContinue` as the FINAL chunk of the response. Consequences: (a) OpenCode finalized the assistant message after the first translated chunk, so the stream-end functionCall flush chunk became a SECOND assistant message — an orphaned functionCall turn in history that Google rejects with HTTP 400 `function call turn comes immediately after a user turn or after a function response turn`; (b) reasoning-only first chunks (deepseek-v4-flash-free) produced `Response text is empty` anomalies + client disconnect (`Chunks: 1`).
    - **`proxy_core/helpers.py`**: `translate_openai_chunk_to_gemini` and `flush_tool_calls_to_gemini` now return `(sse_line, is_terminal)` tuples. Intermediate chunks (no finishReason) carry `willContinue: true`; tool-call completion now emits Gemini-native `finishReason: "TOOL_CALLS"` (was "STOP") for both `tool_calls`/`function_call` finish reasons and the stream-end flush.
    - **`proxy_core/server.py`** (`iter_translated_chunks`): tracks `terminal_emitted` from the tuple returns; if the upstream never sent a finish chunk (only [DONE] or abrupt close), emits a terminal `finishReason: "STOP"` chunk so the client finalizes the turn.

Google rejects this with `Invalid value at 'contents[N].parts[0]' (oneof), oneof field 'data' is already set. Cannot set 'text'` (known SDK bug, googleapis/nodejs-vertexai #494). This occurs regardless of the `compactor_strip_thoughts` checkbox state.
    - **Fix**: Added `split_merged_parts_in_contents` in `proxy_core/compactor.py` which splits any Part combining a data oneof field (`functionCall`/`inlineData`/`functionResponse`/`fileData`/`executableCode`/`codeExecutionResult`) with `text` into separate parts, keeping `thoughtSignature`/`thought` metadata on the data part. Called unconditionally in `process_request_payload` (payload sanitizer, independent of the strip-thoughts checkbox).
    - Added unit test `test_split_merged_functioncall_text_parts` in `test_compactor.py` (all 13 tests passing via @tester).

33. **Strip-Thoughts functionCall Corruption Fix (Gemini 400 oneof, checkbox ON)**:
    - **Root cause**: `strip_historical_thoughts_from_contents` used `if is_thought or has_signature:` — this caught legitimate `functionCall` parts that carry a `thoughtSignature` (Google docs: functionCall parts carry thoughtSignature) and injected `"text": ""` + `"thought": true` into them, producing `{"functionCall": {...}, "text": ""}` — a Part `data` oneof violation → `oneof field 'data' is already set. Cannot set 'text'`. This only occurred when the Strip Past Thoughts checkbox was ON.
    - **Fix**: Only parts flagged as actual thoughts (`thought: true`) are stripped. functionCall/text/inlineData parts that merely carry a thoughtSignature are left EXACTLY as-is. Model turns that become empty after stripping (all signature-less thoughts) are dropped entirely instead of emitting invalid `[{"text": ""}]`.
    - Extended `test_strip_historical_thoughts_preserving_signatures` with a critical assertion: functionCall part with thoughtSignature must remain untouched (no `text`/`thought` added). All 13 tests passing via @tester.

39. **Smart Text Truncation Detection on `finishReason: "STOP"` & Heuristic Hardening**:
    - **Problem**: When Gemini 3.7 Flash consumes output tokens or terminates mid-stream, the API or provider gateway often signals `finishReason: "STOP"` on incomplete code or prose. Because text was present and the finish reason was `"STOP"`, Auto-Continue was bypassed.
    - **Hardening & Fix**: Implemented and hardened `is_response_text_truncated(text: str) -> tuple[bool, str]` in `proxy_core/helpers.py` with rigorous AST/syntax heuristics and explicit rule logging:
      - **Unclosed Code Blocks**: Odd count of triple backticks (` ``` `) -> `UNCLOSED_CODE_BLOCK`.
      - **Trailing Operators / Unclosed Delimiters**: Trailing operators (`=`, `+`, `-`, `*`, `/`, `->`, `=>`, `&&`, `||`, etc., excluding table `|`) or unclosed brackets `(`, `[`, `{` -> `TRAILING_CODE_SYNTAX`.
      - **Trailing Keywords**: Strict statement keywords (`def`, `class`, `return`, `yield`, `raise`, `throw`, `import`, `function`, `async`, `await`, etc.) at the end of the text -> `TRAILING_KEYWORD`.
      - **Unbalanced Delimiters**: Open parentheses, brackets, or braces exceeding closed counterparts (exempting single smileys `:)` with terminal punctuation) -> `UNBALANCED_DELIMITERS`.
      - **Incomplete Sentence**: Long texts ($\ge 100$ chars) ending mid-word without terminal punctuation (`.`, `!`, `?`, `:`, `\n`, quotes, backticks, `…`, `»`, `”`, `’`, `„`, `。`, `！`, `？`, or Unicode Emoji / Symbol categories `So`, `Sm`, `Sk`) -> `INCOMPLETE_SENTENCE`.
      - **False-Positive Exemptions**: Markdown tables ending in `|`, horizontal rules `---`, double-digit numbered lists (`10.`, `11.`, etc.), Russian quotes/ellipsis, and emoji endings are strictly protected.
      - **Explicit Logging**: On truncation trigger, logs rule name and snippet (`[Truncation Detection] Truncated output detected (Rule: REASON, tail: '...')`).
    - **Integration**: Integrated into `stream_generator` in `proxy_core/server.py` so truncated responses trigger Auto-Continue seamlessly.
    - **Unit Test Coverage**: Expanded `test_is_response_text_truncated` in `test_compactor.py` (all 25/25 unit tests passing via @tester).
