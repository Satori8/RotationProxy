## Recent Changes
- **SafeTreeWrapper and SafeNodeWrapper Integration**: Implemented `SafeTreeWrapper` and `SafeNodeWrapper` in `proxy_core/compactor.py` to prevent `builtin_function_or_method` AttributeError issues in headroom AST compression. These wrappers safely check if properties like `.type`, `.children`, and `.root_node` are callable (methods) and call them dynamically if so, ensuring robust duck-typed compatibility across different tree-sitter library versions.
- **is_mixed_content Monkey-Patch Fix**: Moved the `is_mixed_content` monkey-patch out of the `except` block and into the `try` block inside `proxy_core/compactor.py`, ensuring that it actually executes when the headroom module is successfully imported.
- **Beautified JSON Logging in Model Manager**: Updated `on_fetch_free_models` in `proxy_core/gui.py` to read the raw HTTP response as a string, log the beautified JSON response using `beautify_json_string` from `proxy_core.helpers`, and then parse the JSON string, ensuring full visibility and clean formatting of model list responses for all providers (OpenRouter, Ollama, LLM7, Mistral, and OpenCode Zen).
- **Helper Functions Refactoring**: Created a dedicated `proxy_core/helpers.py` module and moved 12 helper functions out of `proxy_core/server.py` (including `truncate_thought_signature`, `beautify_json_string`, `get_session_id`, `get_requested_model`, `extract_chat_messages`, `extract_text_from_chunk`, `extract_token_usage`, `get_next_log_index`, `write_chat_log`, `translate_payload_to_openai`, `translate_openai_chunk_to_gemini`, and `add_anomaly_to_state`), importing them back into `proxy_core/server.py`. This significantly reduces the size of `server.py`, improves code organization, and separates routing logic from payload translation and utility helpers.
- **JSON Beautification in Model Manager Logs**: Added a global helper function `beautify_json_string` in `proxy_core/server.py` that parses JSON strings and formats them with beautiful multi-line indentation (`indent=2`). This helper is applied to all response body logs in `test_model_endpoint` (the model manager test endpoint), making the full response extremely readable and easy to audit directly from the logs.
- **thoughtSignature Truncation**: Added a global helper function `truncate_thought_signature` in `proxy_core/server.py` that uses regex to detect and truncate extremely large cryptographic `"thoughtSignature"` blocks (replacing them with `"<truncated thoughtSignature, length: N>"`). This helper is applied to all raw response logging in `analyze_response_for_anomalies`, model testing logs, and non-200 error logs, completely eliminating log pollution from large signatures.
- **Provider Logging in Completion String**: Added the resolved provider name block (e.g., `[opencode_zen]`, `[openrouter]`) to the standard single-line request completion log string in `proxy_core/server.py` (e.g., `[{provider_name}] [{candidate_model}] [key#{key_index}-{api_key[-4:]}] [200] ...`), ensuring full visibility of which provider handled the request.
- **Path-Based Provider Resolution**: Solved the problem of model name collisions across different providers (e.g., `deepseek-v4-flash-free` existing statically in `MODEL_SETTINGS` for OpenRouter, but requested via `/opencode_zen` for OpenCode Zen). If the request path starts with an explicit provider prefix (such as `opencode_zen/`, `opencode/`, `openrouter/`, `mistral/`, `llm7/`, `ollama_cloud/`, or `ollama/`), the proxy now forces the provider, base URL, and keys pool strictly based on that path prefix, completely bypassing the static `MODEL_SETTINGS` lookup.
- **Detailed Latency Logging**: Integrated precise latency tracking in `proxy_core/server.py`. Measures `Proxy Latency` (time from request receipt by the proxy to sending to the upstream provider, including payload translation, VPN routing, and key rotation) and `Upstream Latency` (time from sending the request upstream to receiving the response headers). These metrics are now appended to all standard request completion logs (e.g., `[200]`), error logs (e.g., `429`, `403`, `503`, `500`), and connection error logs.
- **OpenCode Zen Provider Integration**: Integrated OpenCode Zen as a fully supported provider. Added loading of `OPENCODE_KEYS` from the secure vault file `Opencode Zen API Keys.md` in `proxy_core/rotation.py`. Implemented dynamic model registration and path stripping for `opencode/` and `opencode_zen/` models in `proxy_core/server.py`, forwarding OpenAI-compatible payloads to `https://opencode.ai/zen/v1`. Added `opencode_zen` support to the model testing endpoint and exposed it in the GUI model fetcher dropdown.
- **OpenCode Local Proxy Configuration**: Added `opencode-zen-local` provider to `opencode.json` pointing to our local proxy (`http://127.0.0.1:4000/opencode_zen`), with `deepseek-v4-flash-free` model configured. Verified syntactic validity of `opencode.json` using `json.tool`.
- **Tool Call Anomaly Exclusions**: Excluded `"TOOL_CALLS"` and `"TOOL_CALL"` from being flagged as non-standard `finishReason` anomalies in `analyze_response_for_anomalies` inside `proxy_core/server.py`. Also dynamically detect if the response contains tool calls (`has_tool_calls = True` for both Gemini and OpenAI formats) and bypass the "Response text is empty or only whitespace" anomaly warning in those cases, as empty response text is completely normal when the model returns tool calls.
- **Connection Error Logging**: Enhanced the connection error logging in `proxy_core/server.py` to log the exact exception class name (`type(e).__name__`) and the full traceback (`traceback.format_exc()`) on connection/request exceptions, ensuring that error codes and underlying network/SSL error messages are fully visible in the logs.
- **Anomaly Logging Enhancement**: Added full raw response logging (`[Anomaly Raw Response]`) when a non-standard `finishReason` (such as `TOOL_CALLS`) is detected in `analyze_response_for_anomalies` inside `proxy_core/server.py`, allowing developers to easily inspect the complete server response payload.
- **OpenCode Config Fix**: Resolved a critical syntax error in `E:\Appdata\.config\opencode-profiles\default\opencode.json` where an extra closing brace `}` and a trailing comma after the `"universal-agent"` object caused `JSONDecodeError` and prevented `opencode` from starting up.
- **Headroom Compression Fix**: Resolved a critical architectural issue where raw code, diffs, search results, and HTML files were detected as mixed content by `is_mixed_content` (due to containing both prose/comments and JSON-like braces/brackets) and split into sections. This caused the code sections to be treated as `PLAIN_TEXT` and passed through completely uncompressed because `enable_kompress=False` was set. Monkey-patched `is_mixed_content` to return `False` when the entire content is detected as `SOURCE_CODE`, `GIT_DIFF`, `SEARCH_RESULTS`, or `HTML`, allowing them to be routed directly to their respective high-efficiency compressors (e.g., `CODE_AWARE` or `SEARCH` compression), yielding massive token savings (e.g., 77.5% reduction for `server.py`).
- **Ollama Streaming Fix**: Resolved an issue where streaming responses from Ollama Cloud models (e.g., `ollama/minimax-m3`) were not translated to Gemini SSE format because the proxy didn't inject `"stream": true` into the translated OpenAI payload.
- **Robust Text Extraction**: Rewrote `extract_text_from_chunk` to be completely robust to multi-line chunks, SSE streams, and non-streaming fallback formats (e.g., `choices[0].message.content`).
- **Streamlined Test Suite**: Added comprehensive unit tests for `extract_text_from_chunk` to `test_compactor.py` covering single-line/multi-line SSE and non-streaming formats.
- **Tree-Sitter SafeParserWrapper Fix**: Resolved an infinite recursion hang in `SafeParserWrapper.__getattr__` by adding a guard for `_parser` attribute lookups. Also made `SafeParserWrapper` robust to both bytes-to-string and string-to-bytes conversions, resolving `TypeError: argument 'source': 'bytes' object is not an instance of 'str'` errors across different tree-sitter library versions.
- **Documentation Update**: Updated `README.md` to fully document the latest features including Ollama dynamic routing, manual cooldown bypass, critical safety stop, headroom context compression, tiktoken token statistics, dynamic monkey-patching, tool guardrails injection, and internal reminder relocation.
- **Ollama Dynamic Routing**: Fixed dynamic registration of Ollama models (e.g., `ollama/minimax-m3`) in `proxy_core/server.py` to prevent them from being misrouted to OpenRouter.
- **Manual Cooldown Bypass**: Prevented models from being placed on a 24-hour cooldown when model rotation is disabled (`enable_model_rotation = False`), and bypassed cooldown checks entirely for manual model selection.
- **Critical Safety Stop**: Implemented `track_and_check_safety_limit` in `proxy_core/server.py` to immediately shut down the server process if more than 3 model/server errors occur within a rolling 2.0-second window.
- **Headroom Size Verification**: Added a strict size check to headroom compression in `proxy_core/compactor.py` to ensure compressed content is only used if it is actually shorter than the original.
- **Traceback Logging**: Added full traceback logging to headroom compression errors to easily debug any tree-sitter or library-level warnings.
- **GUI Visibility & Performance**: Set log poll queue interval to `300ms`, optimized sidebar layout, and resolved hidden window rendering bugs.
