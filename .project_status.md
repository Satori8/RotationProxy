# Project Status: GeminiProxy (Resilient Key Rotation Proxy)

## 📊 Current Status
* **Status**: 🟢 Stable & Fully Functional
* **Active Channels**: 7 channels in total (1 clear/non-VPN channel + 6 VPN channels)
* **Active Providers**: Gemini, OpenRouter, Mistral, LLM7, Ollama
* **Parallelism**: 🚀 Enabled & Configurable (1 to 7 parallel channels with numeric delay entry, deterministic key distribution, optimized timeouts, and resilient stream logging)
* **Health Check**: 🩺 Active (1.0s background heartbeat with automatic route and service recovery, Cyrillic output support, and service-state awareness)

## 🔄 Recent Changes
* **Tool Guardrails Injection**: Implemented the Tool Guardrails Injection feature across the codebase. This surgically modifies system prompts (Gemini `systemInstruction` or OpenAI system messages) to replace instructions encouraging generic `read`/`write` on code files and appends strict tool guardrails enforcing optimized tools (`smart-context_smart_read` and `token-savior`). Added a configurable checkbox in the Compactor Settings window in the GUI, tracked injections count in real-time, and exposed stats via `/control/stats`.
* **Full OpenAI Format Support in Compactor**: Upgraded all compaction algorithms (`compact_tools_with_static_map`, `compact_skill_responses`, `compact_devctx_instructions`, `compact_contents_superpowers`, `block_generic_read_on_code_files`, `move_reminder_to_system_instruction`) to fully support OpenAI-format requests (`"messages"`, `"tools"`, `"system"`, and `"role\": \"tool\"`). This ensures that subagent requests (such as `@fixer` or `@refactorer` using Mistral, OpenRouter, etc.) are fully and efficiently compacted.
* **Response Anomaly Detection & Logging**: Implemented a background response analyzer (`analyze_response_for_anomalies`) that runs on every successful `200 OK` response. It parses the streaming chunks to detect anomalies such as non-standard `finishReason` values (e.g., `RECITATION`, `SAFETY`, `MAX_TOKENS`), empty response text, or incorrect response formats (e.g., malformed JSON or SSE streams with no valid chunks), and logs them as warnings to help debug silent agent stops.
* **Russian Windows Encoding Guardrail**: Added a strict instruction to `AGENTS.md` requiring all agents to force transcoding of PowerShell and cmd command outputs to UTF-8 (e.g., by prepending `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8;`) and decode using UTF-8 with fallback, preventing encoding errors and mangled Cyrillic characters on Russian Windows systems.
* **Optimized MCP Tools Analyzer**: Upgraded `tools/analyze_mcp_tools.py` to only scan the *last* request and response files of each session (the ones with the highest chronological index), which contain the complete conversation history. Implemented a robust JSON repair function (`repair_json`) with `re.DOTALL` flags to fix invalid escape sequences (such as backslashes followed by newlines or unescaped Windows paths) and a regex-based fallback parser. This resolved the issue where files with syntax errors were skipped, increasing the detected tool call count from 28 to 96+ unique calls with 100% accuracy.
* **Auxiliary Files Consolidation**: Moved helper scripts (`analyze_duplicates.py`, `analyze_logs.py`, `analyze_session_context.py`, `analyze_session_context_fast.py`, `strip_conversation.py`) and their generated reports/temporary files to a dedicated `tools/` directory to keep the root directory clean and organized.
* **GUI Timeout Settings & Tooltips**: Added Connect Timeout and Read Timeout entry fields to the Settings tab in the GUI, placing them in the second column of the grid. Implemented a custom, lightweight `CTkToolTip` class using standard Tkinter to render hover tooltips in Russian, explaining what each timeout means and recommending values.
* **Resilient Stream Logging & Timeout Optimization**: Fixed silent stream swallowing by propagating exceptions (`raise`) in `iter_bytes`. Added detailed logging of stream start, successful completion, client disconnects (`asyncio.CancelledError`), and network errors. Optimized HTTPX client timeouts with a generous `read=120.0` timeout to support slow free keys with large contexts, and set `keepalive_expiry=30.0` to prevent stale connections in the pool.
* **Ollama Cloud Integration**: Added Ollama Cloud provider with endpoint `https://ollama.com/v1` and keys loaded from `D:\Personal\myvault\90 Private\Sensitive\Ollama Cloud API Keys.md`.
* **Socket-Bound VPN Routing**: Removed the call to `vpn_manager.enable_system_routing_via` during VPN rotation. All 6 VPN tunnels now remain active simultaneously, and traffic is routed via bound sockets (local IPs `10.8.0.11` to `10.8.0.16`).
* **7-Channel Rotation**: Updated VPN rotation to support 7 channels in total (1 clear/non-VPN channel + 6 VPN channels).
* **Optimized Chat Logging**: Prevented generating redundant files. The proxy now only creates `{message_number}_request.txt` and `{message_number}_response.txt` per message, with escaped newlines (`\n`) replaced by actual newlines for human readability.
* **VPN Health Check & Heartbeat**: Implemented a 1.0s background heartbeat loop that checks each VPN channel. If a channel goes down, it automatically runs a fast, non-blocking PowerShell route recovery and service restart with adapter polling.
* **Parallelized Startup**: Parallelized the startup of all 6 VPN tunnels in the GUI. Each tunnel starts and configures its route independently in parallel, reducing startup time by up to 6x.
* **Active Parallelism & Load Balancing**: Added GUI controls to enable parallelism, select the parallel tunnels count (1 to 7), and set per-channel delays. The proxy load-balances requests across active slots and automatically rotates failed slots to backup channels.
* **Cyrillic Output Support**: Configured all PowerShell output captures to set console encoding to UTF-8 and decode using `utf-8` with fallback, ensuring 100% compatibility with Russian Windows system language.
* **Service-State Aware Heartbeat**: The heartbeat loop now checks which WireGuard services are actually running in the system first, and skips checks for stopped or uninstalled tunnels to prevent false alarms.
* **Deterministic Key Distribution**: Implemented a key distribution algorithm that maps active channels to different API keys from the pool, ensuring that parallel channels use different keys and avoid concurrent request limits.
* **Main Screen GUI Layout**: Moved the Parallelism settings (checkbox, dropdown, delay entry) to the left panel (main screen) for instant visibility and control, and removed the obsolete Kaggle URL field and button.
* **Ollama Keys Consolidation**: Consolidated both `OLLAMA_KEYS_FILE` and `OLLAMA_CLOUD_KEYS_FILE` to point to `Ollama Cloud API Keys.md`.
* **Heartbeat Startup Delay**: Added a 30-second startup delay to the heartbeat loop to allow parallel VPN adapters to fully initialize and configure their routes before health checks begin.
* **PowerShell Variable Interpolation Fix**: Fixed a subtle bug where PowerShell variable interpolation was preventing service restarts by using single quotes for the service name (`'WireGuardTunnel$vpnX'`).
* **Numeric Delay Entry**: Replaced the per-channel delay slider with a precise numeric entry field in the GUI, with safe fallback parsing.
* **Combined Ollama Providers**: Combined "Ollama" and "Ollama Cloud" into a single `"Ollama"` provider in the Model Manager, fetching from the cloud endpoint using `Ollama Cloud API Keys.md`.
* **Mistral Provider Integration**: Added `"Mistral"` to the Model Manager, allowing you to fetch and manage Mistral models directly from the GUI.
* **Active State Fallback & Transition Grace Period**: Implemented a global `VPN_ANY_TUNNEL_ACTIVE` state. If no VPN tunnels are active in the system (e.g., when you press "Stop Tunnels"), the proxy automatically and instantly falls back to the unbound client (index 0) and suspends VPN rotation/error tracking. Added a 5-second network stabilization grace period during transitions to allow Windows to restore the physical default route.
* **Model Testing Fallback Fix**: Added the `VPN_ANY_TUNNEL_ACTIVE` fallback check to the `/control/test_model` endpoint, ensuring that model testing also correctly falls back to the unbound client (index 0) when the tunnels are stopped.
