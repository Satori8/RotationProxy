## Recent Changes
- Set the log poll queue interval to **`300ms`** in `proxy_core/gui.py` to drastically reduce CPU usage and polling overhead on the main thread.
- Fixed the **`'dot' is not a valid CodeLanguage`** error in the compactor by monkey-patching `CodeLanguage.__new__` to gracefully fall back to `CodeLanguage.UNKNOWN` when an unsupported language (like Graphviz `.dot` files) is detected.
- Fixed the **`argument 'source': 'bytes' object is not an instance of 'str'`** error in the compactor by monkey-patching `tree_sitter.Parser.parse` to automatically decode `bytes` objects to `str` when the underlying tree-sitter or parser wrapper raises a type error.
- Fixed the **slow ONNX-based Kompress fallback** bottleneck in `CodeAwareCompressor` by monkey-patching `CodeAwareCompressor._fallback_compress` to return a passthrough result instead of loading and running the heavy ModernBERT model. This completely eliminates the 10+ second delays and ensures that code compression is always fast and lightweight.
- Made the GUI window 200px wider and 100px higher (geometry changed from `"900x600"` to `"1100x700"`).
- Made the left sidebar 100px narrower (width changed from `280` to `180`).
- Configured the main window's grid layout columns so that column 0 (the left sidebar) has `weight=0` (fixed width) and column 1 (the right panel) has `weight=1` (expands to fill remaining space), creating a highly professional and responsive layout.
- Optimized all left sidebar widgets (labels, checkboxes, OptionMenus, buttons, and frames) by reducing their padding (`padx` from `20` to `10`) and font sizes (from `12`/`16` to `10`/`12`), and shortening their text labels (e.g., `"Use Kaggle (qwen3.6)"` to `"Use Kaggle"`, `"Enable Parallelism"` to `"Parallelism"`, `"Reset Daily Cooldowns"` to `"Reset Cooldowns"`, `"CONTEXT COMPACTION:"` to `"COMPACTION:"`, `"⚙ Compactor Settings"` to `"⚙ Settings"`) to fit perfectly within the narrower 180px sidebar without any text clipping or overflow.
- Implemented a major GUI performance optimization by hiding the window during initialization (using `self.withdraw()`), building all widgets off-screen, calling `self.update_idletasks()` to perform a single off-screen geometry pass, and then showing the window (using `self.deiconify()`). This completely eliminates visual flickering and incremental "pop-in" rendering during startup.
- Optimized the periodic compactor statistics polling loop (`poll_compactor_stats_loop`) to run on a single long-running background daemon thread with a continuous `while True` loop and `time.sleep(2.0)`, instead of spawning a brand new thread every 2 seconds. This drastically reduces CPU overhead and thread churn.
- Created a comprehensive test suite `test_compactor.py` that thoroughly validates all context compaction stages: static tool map compaction, superpowers block compaction, skill response compaction, generic read blocking on code files, internal reminder moving, tool guardrails injection, and headroom context compression.
- Fixed a bug in `compact_tools_with_static_map` where a `TypeError` would occur if a tool parameter's properties were represented as a string instead of a dictionary. Added robust `isinstance(..., dict)` checks to both Gemini and OpenAI format compaction blocks.
- Fixed Headroom Context Compression for Gemini payloads by directly compressing the `"text"` fields inside `"parts"` AND the `"content"` fields inside `"functionResponse"` parts of Gemini `"contents"` using `ContentRouter.compress()`. This preserves structured tool-use fields (`functionCall`, `functionResponse`, `inlineData`) completely intact, preventing `MALFORMED_RESPONSE` errors, while successfully compressing massive tool outputs (files read, grep results, search results) which make up 99% of the payload size.
- Monkey-patched `headroom.transforms.content_router._detect_content` to use the pure Python regex-based `_regex_detect_content_type` detector, completely preventing hangs caused by the Rust-backed Magika content detector in firewalled/offline environments.

## Restart Loop Investigation (Jun 2026)
- **Finding**: The restart loop (`Proxy server subprocess died with code 1`) is NOT caused by our GUI changes. Our changes only touch `gui.py` and `compactor.py` (function bodies only), neither of which affects the server subprocess lifecycle.
- **Testing**: Server subprocess runs fine standalone (`python proxy3.py` without `--gui` stays alive for 5+ minutes). Subprocess spawned via `subprocess.Popen` with identical params (PIPE, text mode, bufsize=1, startupinfo) stays alive for 5+ seconds. The GUI itself also stays running for 5+ seconds.
- **Root cause**: The restart loop was likely pre-existing but masked by the earlier "GUI not spawning" bug — when the GUI was hidden, the restart loop was invisible to the user.
- **If the restart loop persists**, the most likely cause is an unhandled exception in the server's asyncio event loop during startup (e.g., VPN client initialization, heartbeat task, or proxy handler). The `proxy_errors.log` file captures crash info but currently shows no stderr output because the process exits cleanly without writing to stderr.
